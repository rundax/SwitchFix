# Plan 03 — Reproducible false-positive benchmark

Status: implementation plan; no benchmark has been implemented or executed by this document. Revised 2026-10-19 after review against the baseline.

## Outcome and boundaries

Build a small, local benchmark that answers two separate questions: how often does SwitchFix change intentionally correct input, and how often does it successfully repair an actual layout mistake? Add an optional Klavko comparison using exactly the same labeled trials and explicitly documented configuration. Save machine-readable observations and a readable report; never infer a competitor score when its adapter is unavailable.

The first deliverable must run against SwitchFix alone, without Accessibility permissions, XCTest, a network connection, or a Klavko installation. Use Swift/Foundation and existing targets. Do not introduce a benchmarking framework or change detection thresholds to make a report look better.

Establish the current SwitchFix baseline **before** implementing personal exceptions or dynamic mappings. Freeze those results, implement Plan 02 and then Plan 01 Phase A, and rerun the same corpus and configuration after each. Additional fixtures introduced during implementation belong to development data and a new corpus version; do not quietly alter the original baseline.

## Existing integration points

- `Package.swift` already defines `TestRunner` and `InputPipelineTestRunner` executable targets, with no XCTest dependency. Preserve them and add a similarly small `LayoutBenchmark` executable target depending on `Core`, `Dictionary`, and `Utils`.
- `Sources/Core/LayoutDetector.swift` exposes `addCharacter`, `flushBuffer`, `deleteLastCharacter`, `invalidateSync`, `syncRun`, and `reset`. Its state includes recent context, pending confirmations, allowed layouts, preferred Cyrillic layout, and physical source IDs. A benchmark that checks isolated words only will miss its contextual behavior.
- `Sources/Core/InputStateMachine.swift` is a public, synchronous value type that turns `CapturedInput` into append, flush, invalidate, manual correction, and revert commands. `InputEngine` already accepts `correctionEmission`, exposes `drain`, and carries sequence/context generations. `drain` only flushes the input queue (`InputEngine.swift:268`); detection and correction run on separate queues, so it cannot prove that no correction will follow. An injected `exactDetection` stub is appropriate for harness tests, never for measuring detector quality.
- `LayoutDetector.preferredSourceIDProvider` defaults to `InputSourceManager.shared` (`LayoutDetector.swift:137`), whose initializer enumerates the operator's TIS sources and reads their saved `SwitchFix_preferredInputSources`. The adapter must override it; the default `TextCorrector()` also touches `InputSourceManager.shared`.
- `DictionaryLoader` provides `prewarm`, `enableTextFallbackForTesting`, and `resetForTesting`. Explicit text fallback is suitable for a source-tree baseline, but must be recorded as a dictionary mode, not presented as the installed app's compiled-dictionary measurement.
- Inspected Klavko checkout: `https://github.com/stepsergius/Klavko.git` at `6510e64e5d54b15fbc578bce4830255937b628b4`. The inspected copy lived in `/private/tmp`, which macOS purges; clone it into an ignored path such as `Benchmarks/results/external/klavko` instead. `KlavkoCore.WordAnalyzer` exposes `shouldConvert` and `shouldConvertPrefix`, using `SpellChecking` and `MacSpellChecker`. The app's internal `SwitchEngine` adds context, early conversions, alternative selection, undo, and insertion behavior. Calling `WordAnalyzer` alone does not benchmark that engine.

## Three measurement layers

| Layer | What is measured | What it cannot establish |
| --- | --- | --- |
| Decision | Finished-word decisions with supplied context and source/alternative mapping | Whole-engine behavior, prefix corrections, real insertion safety |
| Sequence replay | Physical-key/event sequence, maintained text/layout state, emitted automatic actions and checkpoints | Successful injection into a real application |
| App conformance | Actual application text and active input source after controlled trials | Large-corpus reproducibility without a dedicated desktop environment |

Publish separate tables. The first layer is a restricted common comparison, not the headline claim that one full application is safer. Sequence observations can be scored only where an adapter implements the actual relevant policy; an approximation must identify itself and remain outside comparative release claims.

## Corpus and labeling contract

Create `Benchmarks/layout-corpus/v1/{development,holdout}.jsonl`, `manifest.json`, and `README.md`. Store one independent trial per JSONL row. A trial can contain several words; contextual sweeps require scoring a run rather than treating every boundary as statistically independent.

Proposed schema, illustrated by a complete positive trial:

```json
{"schemaVersion":1,"id":"uk-positive-001","groupID":"greeting-001","split":"development","languages":["en","uk"],"category":"layout-error","label":"repair","provenance":{"kind":"synthetic","generator":"manual-v1","seed":0,"review":"reviewed"},"initial":{"sourceID":"com.apple.keylayout.ABC","language":"en","text":"","caretUTF16":0,"preferredCyrillic":"uk"},"events":[{"type":"key","keyCode":5,"modifiers":[],"rendered":"g"},{"type":"key","keyCode":4,"modifiers":[],"rendered":"h"},{"type":"key","keyCode":11,"modifiers":[],"rendered":"b"},{"type":"key","keyCode":2,"modifiers":[],"rendered":"d"},{"type":"key","keyCode":1,"modifiers":[],"rendered":"s"},{"type":"key","keyCode":45,"modifiers":[],"rendered":"n"},{"type":"boundary","keyCode":49,"rendered":" "}],"expected":{"text":"привіт ","language":"uk","sourceID":"com.apple.keylayout.Ukrainian","allowedAutomaticActions":["replaceSuffix","switchSource"],"checkpoints":[{"afterEvent":7,"text":"привіт ","language":"uk"}]}}
```

`afterEvent` counts applied events: `7` means the state after the first seven events (here, after the boundary). Event indices in results are zero-based.

Implementation must validate actual installed source IDs before using this example in a live trial. Deterministic rendering uses frozen layout tables shipped with the benchmark: `Benchmarks/layout-tables/v1/<sourceID>@<keyboardType>.json`, one file per source, containing the output of every key code 0..<128 in all eight Shift/Caps/Option states plus rejected strokes. Generate them once with an explicit opt-in `LayoutBenchmark export-layout-tables` command on a real Mac, record macOS version/build and keyboard type in each file, review them against on-screen output, and hash them into the manifest. Never regenerate them silently; a change is a new tables version. Plan 01 consumes the same files as its deterministic fixtures, so the baseline does not wait for plan 01. `rendered` is the initial-source oracle and must equal the table output for that key; validation rejects rows where it does not. Following an automatic switch, physical keys must render through the new source's table rather than continuing to append this original string. Otherwise mid-word switching is measured incorrectly.

Define these labels explicitly:

- `repair`: an intentional layout error with one reviewed expected final text/source. A correct source switch alone is insufficient if the text remains wrong.
- `preserve`: intentional input whose final text and source must remain as typed, with `allowedAutomaticActions: []`. Include natural words, names, code, unfamiliar tokens and accidental-looking but intentional text.
- `abstain`: ambiguity or an unsupported/unsafe context requires no automatic action. These are eligible negatives in a separately reported abstention stratum. Unsupported fixtures for an adapter are instead `unavailable`, never successful abstentions.

Allow multiple expected source IDs only when reviewers explicitly establish equivalence. Do not accept arbitrary output or accept both preservation and conversion for the same trial. Every trial must define expected text, final layout/source, and permitted automatic actions; additionally forbid changes to protected prefixes or ranges. Checkpoints capture temporary damage even when later actions restore the expected final text. Action contracts describe observable effects, not implementation-specific numbers of backspaces.

Add optional event types for delete, navigation, explicit source change, focus/context change, manual correction and revert. Keep automatic-quality scores separate from manual-action conformance. Store timestamps as deterministic relative ticks; timing stress belongs to a separately configured replay profile.

Freeze a 200-trial seed corpus as v1 so the baseline does not wait on a large labeling effort: 100 development and 100 holdout trials, each split containing 20 `repair`, 60 `preserve`, and 20 `abstain` trials. Divide each label equally between English-to-Ukrainian and Ukrainian-to-English contexts. Grow toward 1,000 trials (500/500 with 100/300/100 per split) as v2 and later versions; never edit a frozen version. Use disjoint base groups across splits; generated variants do not count as independent evidence. These sizes establish a regression baseline, not a false-positive claim: zero false positives on the 80 development negatives still has a Wilson 95% upper bound of about 4.6%. Start with independently authored English/Ukrainian positives and negatives in both directions. Keep English/Russian and three-language arbitration as named extensions, not an aggregate that changes the primary comparison. Reserve explicit strata for one-to-three-character words, contextual confirmation, mixed-language sentences, apostrophes/case/punctuation, digits, URLs/email, paths/code, acronyms, names, unknown words, intentional gibberish, deletion/navigation, and back-to-back words. Add mapping variants and personal-exception tests once Plans 01 and 02 land. Unsupported layout combinations receive coverage counts and no quality score.

Labels must derive from intended text and human review, never `WordValidator`, `NSSpellChecker`, or either application's dictionary. Deterministic synthetic generation may render independently authored intended text through verified key maps; do not build the entire corpus from the dictionary being evaluated. Review synthetic positives for ambiguous collisions before assigning `repair`.

Split by `groupID` before generation: a base sentence, its case/punctuation variants, transliterations, reversed mapping and derived prefixes all remain in one split. Hash the frozen corpus. Keep a holdout inaccessible to threshold tuning during development, and record every formal holdout evaluation. Once its individual failures guide fixes, retire it as a development set and version a fresh holdout before making new generalization claims. Public holdouts are useful regression sets but cease to be blind once inspected.

Accept deidentified real examples only through explicit opt-in submission and review. No live keystroke telemetry, clipboard collection or automatic export of exception lists. Remove identifying tokens before commit and retain provenance/consent records outside the public corpus when necessary.

## Adapter and execution contract

Use a versioned JSONL request/result boundary for external programs. Requests contain fixture, profile, dictionary mode and mapping snapshot hashes. Results include adapter/version, capabilities, trial ID, status (`ok`, `unsupported`, `error`), final text/source, ordered actions with event indices, checkpoints, and diagnostic reason codes. Never include private user data in diagnostics. Set protocol version to 1; reject unknown versions, duplicate/missing trial IDs, unknown source IDs, out-of-range event indices, invalid caret/range boundaries, and results for unrequested trials. Bound each request/result line to 1 MiB, trial events to 512, and external worker output to 64 MiB per invocation. Use a 30-second setup timeout and 5-second per-trial timeout after warmup; terminate the worker and mark remaining trials unavailable on process failure. Keep timing limits in the recorded profile, not hidden defaults.

The internal SwitchFix adapter creates fresh detector and source state per trial, prewarms required dictionaries and fails setup if readiness is false. Override `preferredSourceIDProvider` and every other source lookup with values from the trial and the frozen tables; never consult the operator's input sources or defaults. Replay runs synchronously on the real `InputStateMachine` and `LayoutDetector`: feed each event as a `CapturedInput`, handle the resulting commands, apply emitted replacements to a virtual editor, verify the expected suffix before replacing it, apply source switches, and feed the resulting state back to later events. Do not reimplement state-machine rules in the adapter. To avoid duplicating the engine's request assembly (`precedingRun` selection and detector setup, `InputEngine.swift:326–393`), extract it into a small Core function used by both `InputEngine` and the adapter; this refactor must keep both existing runners green.

Cross-check representative traces against `InputEngine` using its real detector and injected emission. Add a test seam, `drainPipeline(completion:)`, that hops input → detection → input → correction queues in order, so a negative trial can conclude "no correction" without a timeout; `drain` alone is insufficient. Use explicit completion assertions; avoid sleeps. If a trace contains asynchronous interleavings that cannot be expressed deterministically, put it in the app/stress suite rather than pretending an arbitrary sleep establishes correctness. Include Plan 01/02 configuration changes through their shared `invalidateCorrectionConfiguration()`/correction-epoch path once available, and verify stale observations cannot emit replacements.

## Controlled profiles and environment capture

1. `boundary-layout-only`: English/Ukrainian only; automatic layout switching on; Klavko `switchWhileTyping` off; spelling, typography, capitalization, spacing, list continuation and replacements off; exceptions empty. Use equivalent supported boundaries. Preserve each detector's own default decision thresholds and disclose them.
2. `native-layout-only`: same scope with Klavko prefix switching enabled and SwitchFix's actual native timing. Feed full key sequences, inspect intermediate checkpoints and report earliest intervention. Never silently disable the competitor's distinguishing behavior in the only published comparison.
3. `personalized`: start from clean profiles, apply the same explicit exception intents and labeled training sequence, then score a disjoint evaluation set. Keep untrained results visible. Plan 02 uses exact original tokens normalized with NFC, lowercase and typographic-apostrophe folding; exceptions form backward-sweep barriers. Explicit hotkey/selection and user-initiated layout-switch correction bypass them. Cover those contracts without forcing Klavko's different prefix-exception behavior into the same semantics.

An optional full-defaults trial may be useful but must classify spelling/formatting changes separately. Differences in feature scope cannot be charged as layout errors by accident.

Record SwitchFix and Klavko SHAs, dirty-tree state, adapter revision, corpus/config hashes, Swift version, build flags, architecture, macOS version/build, keyboard hardware type, input-source IDs/order and mapping hashes, dictionary asset/override hashes and binary/text mode, threshold settings, exception/replacement counts, enabled app/system text services, locale and warm/cold state. Klavko's system dictionary depends on macOS and learned spelling: use a dedicated clean account and record this limitation; do not claim byte-identical system dictionary reproducibility or export private learned words.

## Scoring and interpretation

Score eligible trials, not keys or each repeated correction. Denominators come from validated label/capability eligibility before execution; errors are reported as failures/coverage loss and cannot disappear from reports.

- `N_negative`: eligible `preserve` plus `abstain` trials. Report both strata and their total.
- Text-damage FP rate: negative trials with any unauthorized text mutation divided by `N_negative`, including damage later undone.
- Layout-only FP rate: negative trials with unauthorized source change and no text damage divided by `N_negative`. Also report any unauthorized source change and the union intervention FP rate; distinguish a proposal at decision layer from an applied action at replay/app layer.
- `N_positive`: eligible `repair` trials. TP requires exact expected final text and allowed final source by the checkpoint/deadline, without forbidden intermediate damage. Recall is `TP / N_positive`; all other positive outcomes are FN, subdivided into no action, wrong repair, too late and unsafe mutation.
- Precision is exact successful repairs divided by all trials receiving automatic repair attempts. Its non-TP denominator includes negative interventions and incorrect/partial positive repairs. Label this strict trial-level definition. Return `null` when no repair was attempted. Every rate with a zero denominator is `null`, never zero. A run with missing/error observations must show an incomplete status and cannot pass a quality gate by treating those trials as correct preservation.

Always show counts, coverage, timeout/error counts, micro-average, each direction/category and worst adequately sampled language/direction. Report final-state success separately from damage-free success. A permanently disabled detector has zero FP, zero recall and undefined precision; include that control to prove it cannot win the benchmark.

Use Wilson 95% intervals for proportions and mark small strata inconclusive. With zero FP, show the nonzero upper bound; approximately 3,840 independent negatives with zero events are needed for a two-sided Wilson upper bound near 0.1%. Synthetic variants within one group are correlated: publish group counts and avoid confidence claims treating all variants as independent; use group-level summaries or a deterministic seeded cluster bootstrap for paired score differences. Do not claim superiority from overlapping, low-count or environment-mismatched observations.

## CI and acceptance criteria

Add `.github/workflows/layout-benchmark.yml` on a pinned macOS image with toolchain/environment artifacts. Pull requests run self-checks, schema validation and a bounded development smoke corpus with existing runners. Cache builds only; do not cache private spelling state. Keep the smoke budget below five minutes after compilation; full synthetic corpus and external comparisons are manual/scheduled jobs on an appropriate desktop runner, never a flaky mandatory hosted-UI check. Competitor absence is an explicit skip in optional CI and a failure when a requested comparison requires it.

Initial gates are provisional engineering checks, not product-quality promises: no new known text-damage regressions, no silent coverage loss, no unauthorized changes in safety fixtures, and, while the seed corpus has only 20 `repair` trials per split, no newly failing `repair` trial without a reviewed, recorded explanation. Switch to a percentage recall gate (no drop greater than two percentage points) once a corpus version has at least 100 `repair` trials per split. Inspect each direction and worst sufficiently sampled language, so a good English aggregate cannot mask Ukrainian regressions. Do not promote percentage gates from small strata into confidence claims. Recalibrate thresholds only through a documented corpus/version decision after baseline sizes and uncertainty are known.

Done means the own-code baseline is reproducible from a fresh checkout; every result is traceable to fixtures/config/source; malformed input and missing dictionaries fail visibly; scoring controls detect disabled/wrong detectors; paired comparisons use identical eligible trials with honest capability coverage; and any unresolved Klavko build or engine-access limitation is plainly reported. Full comparative completion additionally requires a real functioning competitor adapter or recorded app trials, rather than an empty comparison table.
